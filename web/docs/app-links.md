# App links (iOS Universal Links / Android App Links)

The web portal serves the association files that let the client mobile app open
`/verify-email` links directly:

- `/.well-known/apple-app-site-association` (iOS, no extension, JSON)
- `/.well-known/assetlinks.json` (Android)

They are generated by the Vite plugin `vite-plugins/appLinks.ts`. In `npm run dev`
and `npm run preview` the plugin serves them; `npm run build` emits them into
`dist/.well-known/`. Nothing lives in `public/`.

## Configuration

Set these as environment variables (shell, CI or Netlify build settings). They are
read at build/dev-server start without the `VITE_` prefix, so they never reach the
client bundle. There is no `.env.example`; this list is the reference.

| Variable | Default | Meaning |
|---|---|---|
| `APPLE_TEAM_ID` | none | Apple Developer Team ID (10 characters) |
| `IOS_BUNDLE_ID` | `com.gfplatform.mobile` | iOS bundle identifier (`mobile/app.json`) |
| `ANDROID_PACKAGE` | `com.gfplatform.mobile` | Android package name (`mobile/app.json`) |
| `ANDROID_APP_SHA256` | none | Comma-separated SHA-256 signing certificate fingerprints |

If `APPLE_TEAM_ID` or `ANDROID_APP_SHA256` is unset, the build still succeeds. It
emits placeholder values (`APPLE_TEAM_ID_NOT_SET`, `ANDROID_APP_SHA256_NOT_SET`) and
prints an `[app-links]` warning. Links will not verify until real values are set.

### Where to find the values

- **Team ID:** developer.apple.com > Account > Membership details.
- **SHA-256 fingerprints:** Play Console > your app > Test and release > App
  integrity > App signing > "App signing key certificate" (SHA-256). If Play App
  Signing is on, Google re-signs the app, so this key is the one users get. Also add
  the "Upload key certificate" SHA-256 if you want links to verify on builds signed
  with the upload key (internal testing, sideloaded builds). Pass both, comma-separated.
  For a local debug build: `keytool -list -v -keystore <keystore>`.

## What the files contain

- AASA: `applinks.details[0].appIDs = ["<TEAM_ID>.<bundle id>"]` and
  `components = [{ "/": "/verify-email*" }]`.
- assetlinks: relation `delegate_permission/common.handle_all_urls`, target
  `android_app` with the package and fingerprints. assetlinks has no path field. The
  `/verify-email` scoping on Android comes from the app's intent filter `pathPrefix`
  (mobile app, not this package).

`/verify-email` itself still renders `VerifyEmailPage` in the browser when the app is
not installed.

## Hosting requirements

Apple and Google fetch these files from the production domain, so:

- HTTPS with a valid certificate.
- No redirects (3xx) on the `/.well-known/*` paths. Apple does not follow them.
- `Content-Type: application/json`. `netlify.toml` sets it for the extensionless AASA
  file (Netlify would otherwise send `application/octet-stream`). Any other host must
  do the same.
- The SPA fallback must not swallow these paths. Real files win over Netlify's
  unforced `/*` rule, so no extra rule is needed.

## Verify

1. `npm run build`, then check `dist/.well-known/apple-app-site-association` and
   `dist/.well-known/assetlinks.json` parse as JSON and hold your real values.
2. `npm run dev` (or `npm run preview`) and request both paths: expect `200` and
   `application/json`, not the SPA `index.html`.
3. On the deployed site, `GET https://<domain>/.well-known/apple-app-site-association`
   must return `200` with `application/json` and no redirect. For Android, check
   `https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://<domain>&relation=delegate_permission/common.handle_all_urls`.
