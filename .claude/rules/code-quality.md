# Rules: Code quality (hard rules)

These are the BLOCKING-severity rules `pr-reviewer` enforces on every
diff. Each finding must follow the strict 4-line shape from the
review-checklist.

## No hardcoded colors

Colors, spacing, font sizes in `/web` and `/mobile` MUST come from
design tokens:

- Mobile: `useTheme()` from `mobile/src/constants/`.
- Web: Tailwind tokens (configured in `web/tailwind.config.ts`).

The brand accent is `#c9a84c` (gold). Never inline; use the theme
entry. Inline `#c9a84c` in a JSX attribute is a BLOCKING finding even
if the value is correct.

## No hardcoded API URLs

API base URLs come from env / config — never literal `https://...`
strings in TS. Web reads from Vite env (`import.meta.env`); mobile
reads from `EXPO_PUBLIC_API_BASE_URL`.

## No `any` in TypeScript

`/web` and `/mobile` are strict-mode TypeScript. `any`, `as any`, and
`@ts-ignore` are BLOCKING findings unless accompanied by a comment
explaining the unavoidable interop reason and a follow-up issue.

## Generated files are write-locked

The following paths are auto-generated by NSwag from the backend's
Swagger and **must not be hand-edited**:

- `web/src/api/generated.ts`
- `mobile/src/api/generated.ts`

A `block-generated-edits` PreToolUse hook rejects Edit/Write/MultiEdit
on these paths locally. `pr-reviewer` flags any diff hunk against them
as BLOCKING. To extend generated behaviour, add wrappers in
`src/api/client.ts` or a sibling module. To change shapes, run the
`regen-api` skill against the running backend.

## No re-layered services

Backend stays vertical-slice. The following patterns are anti-patterns
and BLOCKING for `pr-reviewer`:

- `IRepository<T>` or any generic-repository interface.
- MediatR-style `IRequest<TResponse>` + handlers.
- `Application Services` folder collecting cross-feature logic.
- One feature's `Request` / `Response` / `Validator` imported into
  another feature.

When two features genuinely share logic, extract a small
`Domain/Services/<Topic>Service.cs` (rule of three) and keep it
boundary-injected.

## No swallowed exceptions

Backend always returns Problem Details on error paths. Never `catch
(Exception) { return Ok(); }` or similar. The
`MapProblemDetails`/`Send.NotFoundAsync`/`Send.ValidationErrorAsync`
patterns are mandatory — see [`api-design.md`](api-design.md) when
that rule lands.
